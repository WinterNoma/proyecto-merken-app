# Refresco automático del backend

## Cambios

- `src-tauri/src/recommendations.rs`: descarga y guardado compartidos; cookie de sesión solo en memoria; exclusión mutua de sync y refresco; borrado de sesión ante 401/403; conservación de la copia previa ante fallos de red. Se añadió una prueba de estado sin cookie.
- `src-tauri/src/lib.rs`: registro del comando `recommendations_refresh_backend`.
- `ui/src/ui/recommendations.ts`: refresco cada 15 segundos tras conectar, actualización del roster y evento de snapshot; pausa por invisibilidad, refresco al regresar, detención en pagehide y ante sesión caducada. La interfaz muestra la hora UTC de la copia.
- `ui/tests/recommendations-refresh.test.mjs`: pruebas con IPC simulado para refresco, evento, expiración, modo navegador, visibilidad, respuesta null y pagehide.

## Comprobaciones

- `npx tsc --noEmit -p tsconfig.json`: correcto.
- `cargo check -p merken` y `cargo clippy -p merken --no-deps`: correctos, sin advertencias.
- `cargo test -p merken --lib snapshot_tests::no_session_cookie_is_none`: correcto.
- Los archivos de `ui/tests` pasaron ejecutados individualmente con `node --test --experimental-test-isolation=none <archivo>`. El comando habitual `node --test ui/tests` no pudo crear los procesos hijos (`spawn EPERM` en el sandbox). Al agrupar todos los archivos sin aislamiento, sus DOM globales simulados interfieren; por eso se ejecutaron por separado.
- No se comprobó en una APK ni contra el backend real; no se verificaron el ciclo de vida real en Android ni la expiración de una sesión de producción.
- El entorno mostró directorios no rastreados `crates/local-speech/permissions/autogenerated/` y `schemas/` durante las verificaciones de Cargo; no se incluyeron como cambios solicitados.

## Correcciones tras Sol

- El tratamiento de 401/403 se comparte entre login y descargas de Sync y refresco; invalida la cookie en memoria y devuelve el error de sesión caducada. La UI detiene el temporizador también ante expiración en Sync.
- El refresco conserva el perfil local o el astronauta elegido. Si este deja de estar disponible, vuelve al perfil local y lo indica. La selección automática continúa en Sync manual/inicial.
- Connect pausa el temporizador y espera el refresco pendiente. Una generación invalida sus respuestas anteriores para que no oculten el resultado del Sync.
- Se añadieron pruebas de regresión de UI para los tres casos y una prueba Rust para la invalidación de cookie ante ambos códigos.
- Verificación en esta ejecución: la API de TypeScript con `tsconfig.json` y `noEmit` no informó diagnósticos. No se pudieron ejecutar los comandos de TypeScript, Clippy ni el archivo de pruebas: el entorno rechazó la creación de procesos con acceso denegado (EPERM). Las pruebas y Clippy quedan pendientes de ejecución; no se probó contra el backend real ni en Android.
